# 민재 제트기 게임

게임과 온라인 랭킹을 한 서버, 한 주소에서 실행합니다. 게임에서 별도의 API 주소 입력은 필요 없습니다. 첫 실행 시 랭킹 데이터베이스와 표가 자동 생성됩니다.

## Vercel에 올리기

`vercel.json`에 Framework, Build Command, Output Directory가 포함되어 있어 직접 입력할 필요가 없습니다. GitHub의 main 브랜치를 연결하면 게임 화면과 `api/`의 랭킹 함수가 함께 배포됩니다.

프로젝트의 **Storage → Create Database → Neon**에서 게임 전용 데이터베이스를 만들고 Connect 합니다. 무료 플랜으로 시작할 수 있습니다. 이 프로젝트는 Neon Auth도 사용합니다. 연결할 때 환경변수 접두어는 비워 두고 Production 환경을 포함하세요. 연결 후 재배포하면 첫 랭킹 요청에서 필요한 표를 자동 생성합니다.

서버에서만 `DATABASE_URL` 또는 `POSTGRES_URL`을 사용합니다. 연결 문자열을 소스나 브라우저 코드에 넣지 마세요. Vercel은 로컬 SQLite 대신 Neon PostgreSQL을 사용하며, 재배포해도 온라인 기록이 유지됩니다. 기존 로컬 게임의 기록은 자동 업로드하지 않습니다.

- 빌드: `npm run build` (자동 설정)
- 결과 폴더: `public` (자동 설정, 게임 HTML만 복사)
- 함수: `/api/runs`, `/api/rankings`, `/api/rank/reset`
- 환경: Node.js 24, 데이터베이스와 함수 모두 기본 미국 동부 지역

## 일반 Node.js / Docker 호스팅에 올리기

1. 이 저장소를 **Node.js 24 웹 서비스**로 연결합니다. 정적 사이트 유형은 선택하지 않습니다.
2. 시작 명령을 `npm start`로 지정합니다. 빌드와 외부 패키지 설치는 필요 없습니다.
3. 호스팅에서 발급한 주소를 열면 게임과 랭킹이 함께 작동합니다.

호스팅이 Docker를 지원하면 포함된 Dockerfile로도 실행할 수 있습니다. 호스팅이 지정하는 `PORT`를 자동 사용하며, 기본 포트는 8000입니다. 상태 확인 경로는 `/healthz`입니다.

### 랭킹 기록 보존

일반 실행의 기본 저장 파일은 `online/data/leaderboard.sqlite`입니다. 호스팅이 재배포 시 파일을 지우는 환경이면 **영구 디스크**를 연결하고 `LEADERBOARD_DB`를 그 디스크의 파일 경로(예: `/data/leaderboard.sqlite`)로 지정하세요. Docker의 기본 저장 경로는 `/data/leaderboard.sqlite`이므로 `/data`를 영구 볼륨에 연결하세요. 소스에는 실제 사용자 기록을 포함하지 않습니다.

이 일반 서버 실행 방식은 SQLite를 사용하므로 영구 디스크를 연결한 서버 인스턴스 하나로 운영하세요. Vercel에서는 위의 PostgreSQL 연결 방식을 사용합니다.

### HTTPS와 도메인

게임은 같은 주소의 `/api/`에 자동 연결됩니다. HTTPS 프록시의 `X-Forwarded-Proto`를 처리합니다. 프록시가 원래 도메인 또는 프로토콜을 전달하지 않는 호스팅이라면 `PUBLIC_ORIGIN=https://게임도메인`을 설정하세요(경로와 마지막 슬래시 제외).

## 내 컴퓨터에서 실행

Node.js 24에서 `npm start`를 실행하고 http://localhost:8000 을 엽니다. `npm test`로 HTTPS 프록시 연결, 기록 저장·재시작 복원, 초기화 동작을 확인할 수 있습니다.

## 게임 기능

- 테마별 스테이지, 월드 2, 제트기·부품 상자
- 공격하는 무적 보스에게 최대 60초간 피해를 주는 랭크전
- 랭크전의 11종 잡몹과 자동 코인 획득, 월드 2 코인 2배
- 루키부터 코스믹까지 12종 랭크 배지, 완화된 공격 속도·빈도
- 플레이어별 누적 포인트, 최고 피해, 랭크 초기화
- 전체화면, 방향키 이동, 강화와 기체 진화

## 회원가입과 로그인

로비에서 이메일·비밀번호로 회원가입/로그인하고, 비밀번호 찾기 메일로 재설정할 수 있습니다. 인증은 Neon의 Managed Better Auth가 처리합니다. 게임 서버나 브라우저 저장소에 비밀번호를 저장하지 않습니다.

- 로그인 계정의 랭킹 ID는 서버에서 검증한 서명 토큰으로 결정합니다. 클라이언트가 다른 계정 ID를 지정할 수 없습니다.
- 코인·기체·부품·닉네임은 계정별로 자동 저장됩니다. 다른 기기에서도 로그인하면 불러옵니다.
- 계정에 저장된 기록이 아직 없을 때만 현재 기기의 손님 아이템을 복사합니다. 손님 랭킹은 유지되며 계정 랭킹에 합치지 않습니다.
- 동시 플레이의 오래된 저장은 거부합니다. 충돌 시 로비의 ‘최신 기록 불러오기’를 눌러 서버 기록을 불러오세요.
- 로그아웃하면 기존 손님 아이템으로 돌아갑니다. 손님 기록과 계정 기록은 분리됩니다.

현재 Vercel 프로젝트용 공개 Auth URL과 허용 도메인은 연결되어 있습니다. 다른 프로젝트로 복제할 경우 `NEON_AUTH_BASE_URL`을 새 Auth URL로 지정하고 Neon Auth의 Domains에 새 게임 주소를 등록하세요. 이 URL은 비밀 키가 아닙니다. 로컬 SQLite 서버는 손님 플레이용이며 계정 로그인은 배포된 온라인 게임에서 사용하세요.

손님 플레이어는 브라우저에 저장된 식별자로 구분됩니다. 점수 검증은 기본 범위·시간 검사이며 실제 플레이를 서버에서 검증하는 부정행위 방지 기능은 포함되지 않습니다.
